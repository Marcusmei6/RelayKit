# Privacy

RelayKit is local-first.

## What RelayKit Stores Locally

- Provider configuration metadata.
- Provider credential references, not raw API keys.
- Local usage events generated by the bundled gateway.
- App preferences needed for the menu-bar control surface.

Provider API keys belong in the macOS Keychain. RelayKit provider JSON must store only the Keychain reference, never the real key.

When the RelayKit App starts its bundled gateway, the App resolves only the referenced Keychain items and sends them once through an anonymous stdin pipe. The gateway retains those values in memory for that process lifetime. Credential values are not placed in command-line arguments, environment variables, provider JSON, usage events, diagnostics, or evidence files.

## What RelayKit Does Not Collect

- No cloud telemetry.
- No hosted usage reporting.
- No bundled private provider list.
- No copied `~/.codex/auth.json`.
- No refresh token manager.
- No automatic upload of logs, screenshots, provider config, or usage files.

Official Codex auth stays owned by Codex Desktop. RelayKit may pass through a per-request official auth header when a request already reaches the local gateway, but it must not save the official token or copy Codex auth files.

## What Not To Share

Do not paste any of these into public issues, pull requests, screenshots, release evidence, or chat logs:

- API keys, bearer tokens, cookies, refresh tokens, or private keys.
- `auth.json` or copied auth file contents.
- Raw provider configuration with real domains, account names, or Keychain item names.
- Raw gateway logs that include request bodies or private model/provider identifiers.
- Screenshots showing account identifiers, secrets, or private provider names.

When reporting a bug, prefer the issue templates and redact local paths, account names, provider domains, and request content.
